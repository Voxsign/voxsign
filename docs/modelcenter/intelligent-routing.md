# Model Center · 智能路由与自愈设计

> 依据：模型中心产品讨论结论（2026-10）整理。本文描述目标设计，具体实现随版本迭代。

## 1. 设计出发点

模型调用不是"选个模型就发出去"，而是：

```
任务 → 意图识别 → 建模范型 → 预算判断 → 路由选择 → 执行 → 反馈 → 修正路由
```

每次调用先对任务"建个模"：它是快速决策、深度推理、多模态、还是批量处理？需要速度优先、质量优先还是性价比优先？确定后再路由，并根据模型反馈逐步修正。

## 2. 路由决策（默认接口）

- **触发**：调用方未指定模型（无参数、无偏好）时进入。
- **快速判断层**：毫秒级意图分类，类似快速决策模型（JEV 思路）——先判断"这是什么类型的任务"，不直接生成答案。
- **路由目标**：从已注册模型池中选"当前任务下性价比最优"的模型；同一类任务在不同时间（预算、用量、模型状态变化）可路由到不同模型。
- **决策延迟硬指标**：500ms – 1s。
- **模态支持**：文本、图像等多模态任务分别路由到对应能力模型。

## 3. 异常兜底（异常诊断接口）

任何模型调用出现异常时，进入诊断流程，保证"请求最终有结果"：

1. 收集失败轨迹：任务原文 + 意图 + 工具/参数 + 错误信息 + 被调模型名。
2. 结构化诊断：分类根因（预算 / 网络 / 参数 / 鉴权 / 工具缺失 / 权限 / 瞬时 / 未知），给出置信度与是否可恢复。
3. 建议下一步动作：
   - `retry`（最多 2 轮，可带修正参数）
   - `modify`（改参数或提示词重试）
   - `fallback`（切到备选模型）
   - `ask`（需要更多信息）
   - `stop`（不可恢复，返回友好文案 + 下一步建议）
4. 兜底保障：诊断接口自身故障时自动跳过，不影响原链路。

### 自愈与性能

- 自愈：对瞬时错误自动重试、对预算/鉴权类错误给出可操作提示、对模型不可用自动切换备选。
- 性能：诊断决策 500ms – 1s；超时即降级到确定性兜底，不让调用方无限等待。
- 监控：持续记录各模型在线/离线、延迟分布、成功率，作为路由与学习的输入。

## 4. 自我学习（学习接口）

- **输入**：当前模型池清单、各模型用量与预算消耗、调用成功率与延迟、错误分布、外部新模型发布信息。
- **输出**：
  - 模型池更新建议（新增 / 下架 / 降级为备选）；
  - 路由策略调整（某类任务默认模型切换）；
  - 预算与用量跟踪结论。
- **执行方式**：调用当前可用的最强学习型模型，定期（按策略触发）运行，结果经确认后写入路由配置。
- **目标**：模型中心随使用与外部模型演进持续自优化，而不是依赖人工维护静态清单。

## 5. 状态对外可见

对外提供状态/能力接口，让外部使用者了解：

- 当前哪些模型可用、什么版本、是否在线；
- 每个模型的性能概览（延迟、成功率）与适用场景；
- 模型池与路由策略的最近变化。

## 6. 演进路线

| 阶段 | 内容 |
|---|---|
| P0 | 三接口（默认 / 异常 / 学习）落地，测试桩验证，接入现有调用链路 |
| P1 | 学习接口定期运行，模型池自动更新，路由策略可解释 |
| P2 | 多模态与专项任务路由完善，预算感知的自动降级与告警 |
