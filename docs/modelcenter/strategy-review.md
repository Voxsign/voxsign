## 2. 四议题：双视角对比与综合结论

### a) Go 网关重写 vs 保留 Python 网关渐进增强

| 视角 | 结论 |
|---|---|
| 架构战略 | 终态选 Go 正确；"绞杀者模式并行迁移 + 压测门控切流"，不一次性重写、也不长期留恋 Python |
| 工程实施 | 不做推倒重写；Go 网关并行按流量灰度、Python 保留随时切回；重写为扩容与路由复杂度做准备，非救火 |

**综合结论：绞杀者迁移（strangler migration）。** 依据：
1. 今日瓶颈在模型侧（全链路超时分层：网关 2s → 模型 30–120s，见 architecture-plan §3.3），网关转发多花 30–50ms 占单次 <1%；重写收益是并发/流式/HTTP2 连接池/P99 稳定（为 QPS 上涨与路由内嵌做准备）。
2. 现有网关小、在线稳定（self-healing §6：`/` 200、队列 55/failed 0），重写回归风险 > 边际收益；CPU 77.8% 有信号但未到临界。
3. **观测基线未落前重写 = 盲改**：无 P95/成功率/错误分布基线就无法证明"变好还是变差"——这是把 Go 化排在 P1（观测之后）的铁律。
4. 目标硬指标（转发 <10ms、本地兜底 <1ms、流式/背压）只有 Go 能干净达成，越晚迁移迁移面越大。

### b) 毫秒级智能路由（L0→L1→L2）是否最佳路径

| 视角 | 结论 |
|---|---|
| 架构战略 | 是——成本感知级联标准形态，独有演进红利：学习闭环把高频正确决策"编译"进 L0，越用越快 |
| 工程实施 | 骨架正确，但落地顺序反过来：先 L0+L2 跑稳，L1 后置（甚至先用规则/统计代理） |

**综合结论：三层骨架采纳，L1 后置 + 硬约束。** 依据：
1. L0 本地规则 <1ms 兜住确定性意图 → L1 轻量判断 10–50ms 仅在 L0 未命中时触发 → L2 查本地缓存直发；绝大多数请求 <1ms 解决。
2. **L1 必须共址/本地部署、50ms 硬超时、禁止远程 LLM**（一次网络往返即爆 500ms–1s 预算）；L1 失败/超时秒降 L0 保守默认。
3. **健康/预算缓存：TTL + 硬事件推送式失效**（余额=0 / auth 失败触发即清缓存，不能等定时刷新——否则会把钱打给欠费模型）；缓存缺失走保守默认、不阻塞。
4. 路由先**影子灰度**（记录"若新路由会选谁"算命中率，不真改流量），达标再小比例分流。
5. P3 学习闭环的产物（高频正确决策）显式"晋升"进 L0 规则库——这是三层结构独有的越用越快红利。

### c) Harness 驻留自我迭代（开发维护工程师）的价值/风险/正确姿势

| 视角 | 结论 |
|---|---|
| 架构战略 | 品类级战略价值（网关被 AI 自己维护），但必须最后上线；"强建议权 + 受限执行权" |
| 工程实施 | 价值真实但必须是 P4；权限锁死 + 变更必审批 + 一键回滚 + 迭代预算封顶四件套 |

**综合结论：方向拍板不变，P4 进场 + 四把锁。** 依据：
1. **递归风险是本系统独有硬伤**：Harness 调用的模型正是它维护的网关路由，改错快路径 = 自宕机。
2. **依赖链**：无 P0 观测无法验证改动好坏；无 P3 灰度/自动回滚 = 裸奔。这是排最后的工程理由，不是客气。
3. **正确姿势**：生产只读、预发可写；变更走 PR→（规则/人）审批→灰度→一键回滚（git 化、有版本号）；迭代预算：每日次数上限、连续 2 次指标不改善即熔断告警；上线前先 1 周 dry-run（只出建议不部署）；禁止自改路由快路径与熔断核心；每次自改强制落决策日志并反哺学习样本库。
4. 奖励黑客风险（被成本指标诱导导流最便宜模型、质量静默下滑）→ 先有质量护栏（模型裁判/蒸馏回归测试）才配写权限。

### d) 落地顺序 P0→P1→P2→P3→P4 是否合理

| 视角 | 结论 |
|---|---|
| 架构战略 | 主框架合理采纳；两处修正：P1 门控切流（压测达标才切）；自愈韧性安全网先于智能路由成型 |
| 工程实施 | 大顺序合理（与 architecture-plan §6 一致）；修正：P0 必须含异常诊断桩 + 转发 P95 基线埋点；P1 是并行灰度替换非一次性切换 |

**综合结论：主框架保留，统一主线 + 每阶段验收门（见 §3）。** 关键修正：
1. **P0 必须含"异常诊断桩 + 转发 P95 基线埋点"**——三份文档子阶段口径不一（self-healing §7 / observability-learning §8 / architecture-plan §6），合并为一条主线，P0 验收 = 调用统计可见 + 异常有轨迹 + 迁移前基线落库。
2. **韧性先于智能**：self-healing 动作集（重试≤2 → 同池切换 → 确定性兜底 <1ms → 下线告警）必须先于 P2 智能路由成型，否则第一次 L1 误判就是生产事故。
3. P1 是"压测门控切流的并行灰度"而非"默认切 Go"；不达标继续 Python 迭代。

## 3. 综合最优方案（一页）

**策略五要点：**
1. **不重写，绞杀者迁移**：Go 薄转发层并行 + 压测门控切流，Python 保留回滚路径。
2. **观测先行**：P0 结构化调用留痕 + 转发 P95 基线 + 异常诊断桩，一切改造以基线为证。
3. **韧性先于智能**：自愈动作链先于智能路由成型，路由层可激进、自愈层保守兜底。
4. **三层路由、L1 后置**：先 L0+L2 确定性快稳，L1 共址 + 50ms 硬超时 + 推送式缓存失效；学习闭环把高频决策编译进 L0。
5. **Harness P4 受限进场**：强建议权 + 受限执行权 + 四把锁（权限/审批/回滚/预算）。

**统一主线（合并三份文档口径）：**

| 阶段 | 内容 | 验收门 |
|---|---|---|
| P0 | 观测采集 + 看板 + 异常诊断桩 + 转发 P95 基线 | 调用统计可见、异常有轨迹、迁移前基线落库 |
| P1 | Go 薄网关并行灰度（1%→10%→50%）+ 自愈动作集骨架 | 转发 <10ms、吞吐 ≥2× Python、错误率不劣化（压测达标才切流） |
| P2 | L0 规则 + L2 健康/预算本地缓存（TTL+推送失效）；L1 后置占位 | 默认路由 500ms–1s、路由留痕、超时/缺缓存自动降级确定性兜底 |
| P3 | 对比测试 + 蒸馏样本库 + 学习闭环（灰度生效、变差自动回滚） | 路由策略自动更新且可解释、样本脱敏合规 |
| P4 | Harness 受限驻留（dry-run 先行） | 一次改造指令全自动闭环且不影响生产指标 |
