# Model Center · 高性能建设规划

> 状态：规划稿 v1（2026-10）。本文是模型中心从"可用"到"高性能 + 智能"的建设蓝图，与
> [intelligent-routing](intelligent-routing.md) / [self-healing](self-healing.md) / [observability-learning](observability-learning.md) 三份设计衔接。

## 1. 建设目标

把模型中心建成：**高性能网关 + 智能路由 + 自愈 + 自我学习** 的统一模型入口。

| 目标 | 硬指标 |
|---|---|
| 路由决策延迟 | 默认路由 500ms–1s；毫秒级意图判断附加 <50ms |
| 网关转发开销 | 单次 <10ms（本地兜底 <1ms） |
| 吞吐 | 高并发（连接池 + 流式 + HTTP/2），P99 稳定 |
| 可用性 | 任何模型异常最终有响应（自愈闭环） |
| 智能 | 统计→发现→对比→蒸馏→路由优化闭环（学习接口驱动） |

## 2. 总体架构（五层）

```
接入层     OpenAI 兼容网关（/v1/chat/completions）——高并发、低延迟、鉴权
路由层     意图识别(毫秒级) → 任务建模 → 预算判断 → 模型选择 → 反馈修正
模型层     多供应商适配器（OpenAI / Claude / Gemini / 千问 / 本地模型）
观测层     调用日志(结构化) → 指标 → 看板 → 蒸馏样本库
学习层     学习接口(最强学习模型) → 策略更新 → 灰度 → 回滚
```

- 接入 + 路由：**无状态**，可水平扩展；
- 模型层：供应商适配器隔离（重试/降级/限流策略内聚）；
- 观测层：日志先行，指标聚合，样本脱敏入库；
- 学习层：与观测层闭环，产出路由/模型池/预算建议。

## 3. 技术选型与性能关键点

### 3.1 网关与路由层：Go 优先

| 项 | 选择 | 理由 |
|---|---|---|
| 网关语言 | **Go** | 高并发原生支持、低内存、毫秒级转发；与现有 Python 网关做压测对比（P50/P95/QPS/内存）后替换 |
| 路由决策 | Go 内嵌（本地规则 + 轻量模型调用） | 快路径 <1ms，不引入跨进程开销 |
| 状态共享 | Redis（或本地内存 + 定期落盘） | 模型健康、路由映射、预算快照——避免每次查询上游 |
| 供应商调用 | HTTP/2 + 连接池 + 流式 | 首 token 延迟与吞吐双优化 |

### 3.2 毫秒级路由决策（三层快路径）

```
L0 本地规则（<1ms）       ：任务关键词/正则 → 确定性映射（如翻译→指定模型）
L1 轻量意图模型（10-50ms）：JEV 类快速决策，判断任务类型与预算档位
L2 路由执行              ：按 [任务类型 × 模型健康 × 预算] 查缓存映射 → 发出
```

- 模型健康与预算：**本地缓存 + 定时刷新**，路由决策不依赖实时上游查询；
- 缓存失效兜底：缓存缺失时走保守默认路由，不阻塞。

### 3.3 兜底与降级

- 本地确定性兜底（规则/缓存）<1ms，保证"最终一定有响应"；
- 异常诊断接口决策 500ms–1s（已设计，见 self-healing.md）；
- 全链路超时分层：网关 2s → 模型 30-120s → 流式首 token 单独计时。

## 5. Harness 自我改造（开发维护工程师）

模型中心内置一个长期驻留的 Harness 角色——**开发维护工程师**：

- 驻留模型中心，持续监控（日志/指标/告警）；
- 收到"改造目标"即自我实现：改代码 → 测试 → 部署 → 验证 → 记录；
- 每次异常与优化动作都沉淀为经验（决策日志），驱动自身迭代；
- 角色与域（domain）按进程关联，多进程各司其职。

意义：模型中心不只被 AI 调用，也被 AI 维护——能力随使用持续进化。

## 6. 演进路线

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 · 现状加固 | new-api + 网关在线；观测接入（指标看板）；异常诊断桩接入 | 调用统计可见，异常有兜底轨迹 |
| P1 · Go 网关 | Go 网关替换/并行，压测对比（P50/P95/QPS/内存） | 转发开销 <10ms，吞吐 ≥2× Python |
| P2 · 智能路由 | L0/L1/L2 路由落地；预算感知；模型健康缓存 | 默认路由 500ms–1s，毫秒级判断生效 |
| P3 · 学习闭环 | 对比测试 + 蒸馏 + 学习接口定时驱动 | 路由策略可自动更新，灰度+回滚 |
| P4 · Harness 驻留 | 开发维护工程师驻留，自我迭代 | 一次"改造指令"全自动闭环 |

## 7. 风险与取舍

| 风险 | 缓解 |
|---|---|
| Go 网关重写周期长 | 先并行灰度，保留 Python 网关回滚路径 |
| 路由误判（轻量模型判断错） | L0 规则兜底 + 灰度 + 反馈修正样本 |
| 蒸馏样本隐私 | 一律脱敏入库，不含客户数据/凭据 |
| 预算失控 | 预算快照 + 阈值阻断（blocked 机制已有雏形） |
