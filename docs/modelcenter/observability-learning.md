# Model Center · 观测 · 蒸馏 · 对比测试 · 路由优化

> 状态：设计稿（2026-10）。目标：让模型中心"越用越聪明"——从每次调用中学习，自动发现问题、对比模型、优化路由。

## 1. 核心问题

- 模型中心被调用时，各种数据有没有记录？
- 能不能从调用数据发现问题、提优化建议、做路由？
- 能不能"蒸馏"调用经验，做对比测试，知道哪个模型效果好、哪个差？

## 2. 数据层：每次调用都留痕

**调用记录**（每次请求落一条结构化日志，现有 `/opt/modelcenter/logs/` 基础上补齐字段）：

| 字段 | 说明 |
|---|---|
| 模型名 / 版本 | 实际被调模型 |
| 任务类型 | 意图分类（快速决策/深度推理/多模态/批量…） |
| 输入输出摘要 | **脱敏后**留存（可复现测评，不泄露内容） |
| 延迟 | 首 token / 总耗时（P50/P95） |
| token 用量 | 输入/输出/缓存 |
| 费用 | 单次成本（按模型定价） |
| 结果 | 成功 / 失败 / 重试 / 切换 / 降级 |
| 错误类别 | 9 类（budget/network/param/auth/tool_missing/permission/transient/unknown/quality） |

**聚合指标**（new-api 中转层已带 token 统计，接入统一看板）：
- 按模型：调用量、成功率、延迟分布、费用、错误分布；
- 按任务类型：哪个模型在该类任务上表现好/差；
- 按时段：用量趋势、费用趋势、预算消耗。

## 3. 发现问题（规则 + 统计异常）

- 规则触发：成功率 < 阈值、P95 超限、余额逼近阈值、某类任务反复失败；
- 统计发现：费用异常增长、模型用量骤降（可能被路由冷落或出问题）、错误类别漂移；
- 输出：问题清单 + 可能原因 + 建议动作（自动生成，进入诊断接口语义）。

## 4. 对比测试（哪个模型好、哪个差）

**两条线并行**：

| 方式 | 说明 |
|---|---|
| 离线压测（已具备雏形：waterfall 测试） | 固定任务集 → 各候选模型 → 比质量分、延迟 P50/P95、成功率、费用/token |
| 线上 A/B | 同类型任务流量按比例分流给候选模型 → 匿名对比 → 测评报告 → 决策 |

**测评维度**：质量（模型裁判/人工抽样）、延迟、成功率、成本、适用任务类型、稳定性。

**产出**：模型排行榜（按任务类型）—— 直接驱动路由与模型池调整。

## 5. 蒸馏（样本库）

- 把"好调用对"沉淀下来：`任务描述 → 被选模型 → 高质量输出 → 低成本`；
- 构成样本库（distill pool），用途：
  1. 对比测试的标准任务集（不用临时造题）；
  2. 路由策略的评估集（验证路由改动是否变好）；
  3. 未来提示词优化、策略微调的候选语料；
- 隐私纪律：**输入输出一律脱敏后入库**，不含客户数据/凭据。

## 6. 路由优化闭环（学习接口驱动）

```
调用统计 → 发现问题 → 对比测试 → 样本库 → 学习接口产出建议
→ 路由/模型池/预算调整 → 灰度生效 → 观察指标 → 回滚或固化
```

- 建议类型：路由切换（某类任务换默认模型）、模型池增删（新增/下线）、预算调整、参数优化；
- 灰度：先小流量验证，指标变好才全量；变差自动回滚；
- 学习接口 = 三大对外接口之一，调用最强学习模型定期执行本闭环（P0 手动触发 → P1 定时 → P2 自动确认）。
