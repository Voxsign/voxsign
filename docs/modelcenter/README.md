# Model Center · 模型中心

统一模型网关：对外提供 OpenAI 兼容接口，对内统一管理多家模型供应商（OpenAI / Anthropic Claude / Google Gemini / 千问 等）的调用、路由、异常兜底与自我学习。

> 本文档描述对外能力与接口设计。实现状态以线上网关为准，接口细节随版本演进。

## 对外能力

| 能力 | 说明 |
|---|---|
| 标准调用 API | OpenAI 兼容 `POST /v1/chat/completions`，指定任意已注册模型名 |
| 默认接口（智能路由） | 不指定模型时，快速意图识别 → 自动选择性价比最优的模型完成调用 |
| 异常诊断接口 | 任何模型调用异常时的兜底：分类根因、给出下一步动作建议，确保请求最终被处理 |
| 学习接口 | 自我学习：持续评估模型状况、用量、预算与最新可用模型，优化路由决策 |
| 状态能力接口 | 对外暴露当前可用模型清单、在线状态与性能概览 |

## 三大核心接口

### 1. 默认接口（智能路由）

- 语义：调用方不指定模型、不传参数时的默认入口。
- 行为：先做轻量意图判断（毫秒级），再按"速度 / 质量 / 性能 / 模态"偏好路由到最合适的模型。
- 目标：默认路径的决策延迟控制在 500ms – 1s 以内。
- 设计原则：调用前先建模（意图、预算、可用模型池），再据模型反馈逐步修正路由策略。

### 2. 异常诊断接口

- 语义：被调模型出错、超限或不可用时的兜底入口，保证"最终一定能对外提供服务"。
- 行为：接收失败轨迹（任务原文、意图、工具/参数/错误、被调模型名），返回结构化诊断。
- 输出：`category`（budget / network / param / auth / tool_missing / permission / transient / unknown）+ `root_cause` + `confidence` + `recoverable` + `suggestion` + `action`（retry≤2 轮 / modify / fallback / ask / stop）+ `retry_params`。
- 规则：`recoverable=false` 一律 `stop`，返回友好文案与下一步建议；接口本身异常时自动降级，现有链路行为不变。
- 性能硬指标：诊断决策 500ms – 1s。

### 3. 学习接口

- 语义：模型中心自我优化的入口，调用最强的学习型模型。
- 行为：定期评估现有模型状况与用量、预算消耗、最新发布模型，产出路由建议并更新模型池。
- 目标：让模型中心随使用持续变好（自愈 + 自我学习），而非停留在静态模型清单。

## 智能调用方式

- 模型能力本质是"拆分 → 规划 → 执行"：每次调用前先判断任务类型（快速决策 / 深度推理 / 多模态 / 批量），再决定用哪个模型与什么参数。
- 对"默认调用"建立独立的路由模型（类似快速决策模型 JEV 的思路），在毫秒级完成意图判断与路由，再交给执行模型。
- 被调模型若明显过时或质量不足（如发布超过半年、无法解答任务），自动切换或告警反馈，不静默失败。
