# VoiceSign Harness · 域（Domain）与角色（Role）

> 状态：概念稿 v0.1（2026-10）。核心约束：**没有角色，Harness 没有方向；没有域，Harness 是失控的老虎。** 本文先立概念框架，架构设计中继续完善。

## 1. 为什么必须有域和角色

Harness 是驻留式智能体（长期在线、自主行动）。自主 = 风险：

- 只给目标不给边界 → 它可能碰不该碰的东西（数据、资金、外部动作）；
- 只给边界不给目标 → 它不知道要往哪走，空转或乱跑。

所以每个 Harness 进程必须**同时绑定 {角色, 域}**：

| 概念 | 回答的问题 | 本质 |
|---|---|---|
| **角色 Role** | 这个进程为什么存在？核心目标是什么？为谁达成什么？ | 使命 / 方向 |
| **域 Domain** | 它能做什么、不能做什么？可访问哪些资源、可执行哪些动作？ | 边界 / 权限 |

> 一句话：**角色定"要做什么"，域定"能做什么"**。目标牵引，边界约束，缺一不可。

## 2. 角色（Role）——使命与核心目标

- 每个进程一个明确角色，用一句话写清：**为谁、达成什么**。
- 角色决定这个进程日常做什么、优先级怎么排、产出给谁。
- 示例：
  - 模型中心 Harness → 角色 = **开发维护工程师**：让模型中心保持可用、持续优化（监控→改造→验证→记录）。
  - 研究引擎 Harness → 角色 = **研究员**：把任务入队、产出研究结论。
  - 文档 Harness → 角色 = **文档维护者**：把确认内容发布到指定仓库。

## 3. 域（Domain）——边界与权限清单

域必须**显式、可机器校验**，至少包含：

| 维度 | 内容示例 |
|---|---|
| 可访问资源 | 哪些目录/服务/仓库/API（allow） |
| 可执行动作 | 改代码/部署/发消息/写文件/调模型（allow） |
| 明确禁止 | 客户数据、资金、外部消息、越权改动（deny，硬边界） |
| 副作用等级 | 本地可逆 / 高风险需人批 / 不可逆禁止 |
| 异常处理 | 越域动作 → 立即停止 + 告警 + 留痕（不静默继续） |

## 4. 落地机制（与现有系统衔接）

- **绑定**：每个 Harness 进程启动时加载自己的 `{角色, 域}` 定义（配置文件）；
- **校验**：动作执行前强制过域检查（参照 execution_permission_gate：资金/不可逆/对外 → 问人）；
- **审计**：所有动作留痕（决策日志 / 告警流 / 状态接口可见）；
- **演进**：域可以随角色成熟度逐步放宽（先只读监控 → 再小范围改动 → 再扩大），但每次放宽需人确认。

## 5. 与 AIOps 认证体系呼应

已有基础：AIOps `keys.json` 的 caller → `role: agent|tenant` 即角色雏形；执行权限门（资金/不可逆/对外→问人）即域的雏形。本概念把两者**统一成 Harness 级的第一公民**，所有驻留智能体强制遵守。
